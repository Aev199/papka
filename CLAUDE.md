# Papka — правила работы

Papka — файловый менеджер для Windows на Rust + GPUI (gpui-ce 0.2.2,
gpui_ce_components 0.2.0). Интерфейс, сообщения, заметки к выпускам и ответы
пользователю — только на русском. Пользователь работает с iPhone и проверяет
выпуски на Windows; сам запустить Papka на Windows Claude не может.

## Ветка и git

- Работать только в ветке `feat/native-gpui-foundation`. В `main` не сливать,
  PR не создавать, пока об этом не попросят.
- Каждый ход заканчивать коммитом и `git push -u origin feat/native-gpui-foundation`.
- Сообщения коммитов — на английском, кратко о сути изменения.
- `cargo fmt` не запускать: код оформлен вручную.
- Репозиторий переименован в `Aev199/papka`; старый адрес `Aev199/filemanager`
  переадресуется. Если доступ сессии выдан на старое имя — пушить и запускать
  сборки через него.

## Сборки и выпуски — только в конце

- **Не собирать выпуск после каждой правки.** Исправления копятся в ветке;
  сборка запускается один раз, когда пользователь говорит «выпуск» / «собери»
  или когда закрыта вся порция задач из его сообщения.
- Перед сборкой — все проверки ниже; в ответе перечислить, что войдёт в выпуск.
- Если пришла новая правка, пока сборка идёт: дождаться её окончания или
  включить правку в следующий выпуск; не отменять сборки без причины.
- Сборка: GitHub Actions, workflow `windows-portable.yml`, ветка
  `feat/native-gpui-foundation`, запуск вручную (`workflow_dispatch`) с
  входами `channel` (`beta` по умолчанию, `stable` — когда просят выпуск для
  всех), `publish: true`, `notes` — пункты на русском через `;`.
- Версия = `0.1.<номер запуска>`; отменённые запуски тоже занимают номер.
- Подробности обновлений и ссылок на файл: `docs/UPDATES.md`.

## Проверки перед коммитом

```
cargo test --workspace
cargo check --workspace --all-targets --target x86_64-pc-windows-gnu
rustc --edition=2024 --test crates/desktop/src/layout.rs -o /tmp/lt && /tmp/lt
rustc --edition=2024 --test crates/desktop/src/palette.rs -o /tmp/pt && /tmp/pt
```
После Windows-проверки удалять `target/x86_64-pc-windows-gnu` — диск
контейнера маленький (`target/debug` растёт до 20+ ГБ; при нехватке места
удалять старые файлы в `target/debug/deps` и `target/debug/incremental`).

## Проверка интерфейса (Linux, Xvfb)

- `tools/ui-smoke/run.sh 97` запускает приложение (окно появляется через
  15–25 с), `tools/ui-smoke/ui.sh 97 <папка> click X Y | key K | type T | wait S | shot NAME`.
  `type` — только латиница; переход по папкам — Ctrl+P или мышью.
- Остановить: `kill $(pgrep -f "^/home/user/filemanager/target/debug/filemanager-desktop")`
  (не `pkill -f filemanager-desktop` — он убивает и собственную оболочку).
- Видимые изменения проверять скриншотом до выпуска.
- Windows-только вещи (перетаскивание, Shell, предпросмотр Office/PDF,
  обновления, диски) здесь не проверяются — так и говорить пользователю.

## Устройство и ограничения

- Крейты: `crates/core` (логика, тесты), `crates/desktop` (GPUI),
  `crates/cli`; `vendor/gpui_ce_windows` — пропатченный крейт (см. его PAPKA.md).
- Никогда не хранить содержимое файлов: история и лента — только метаданные.
- Не удалять данные пользователя и профиль (`%LOCALAPPDATA%\Papka`).
- В GPUI нельзя дважды вызывать `.hover()` на одном элементе — паника.
- Ручной чек-лист для пользователя: `docs/SMOKE_TEST.md` — дополнять
  пунктом при каждой новой функции.
