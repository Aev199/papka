# Вставка файлов из RDP и виртуальных поставщиков буфера Windows

Причина: обычная вставка Papka принимает CF_HDROP (локальные пути), тогда как
RDP может отдавать FileGroupDescriptorW/FileContents без локальных путей.

Новый путь Ctrl+V:

1. Проверить наличие FileGroupDescriptorW или FileGroupDescriptor без чтения
   содержимого на UI-потоке; запомнить номер изменения буфера.
2. На отдельном STA-потоке получить IDataObject через OleGetClipboard и проверить,
   что буфер не подменён между нажатием Ctrl+V и захватом объекта.
3. FileGroupDescriptorW/FileContents читаются через OLE IStream (либо HGLOBAL)
   в собственный TempDir; для ANSI-дескрипторов используется Windows code page.
   Относительные имена проверяются на выход из каталога, ADS и имена устройств;
   проверяются ошибки и заявленные размеры потоков. На этом этапе используется
   штатное окно прогресса/отмены Windows. Для файловых Shell-объектов остаётся
   путь IFileOperation.CopyItems.
4. После успешного получения передать локальные файлы обычной аудируемой очереди
   Papka: конфликты, параллельность, отмена и Undo работают как для обычной копии.

Источник не перемещается и не удаляется. Неполное получение/ошибка отдельного
элемента/отмена не запускают копирование в выбранную пользователем папку.
Временная папка удерживается активной/ожидающей передачей и её повторами после
сбоя; освобождается после завершения или отклонения. Нужен запас места для
промежуточной копии; большие файлы не загружаются целиком в оперативную память.

Тесты Windows: настоящий IDataObject с FileGroupDescriptorW/FileContents/IStream
без CF_HDROP, файл и вложенная папка с кириллицей; файловый Shell IDataObject,
последующая аудируемая копия; отказ при частичном сбое поставщика; смена номера
буфера. Глобальный системный буфер этими тестами не перезаписывается.

Реальное RDP-соединение в CI отсутствует. Перед выпуском вручную проверить
одиночный файл, папку с подпапками, несколько объектов, большой файл, конфликт
имён, отмену и обрыв соединения; также обычные Ctrl+C/Ctrl+X из Проводника.

Документация API:
- https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-copyitems
- https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-olegetclipboard
- https://learn.microsoft.com/en-us/windows/win32/shell/clipboard

Обычный CF_HDROP имеет приоритет, чтобы Ctrl+X из Проводника сохранял семантику
перемещения. Если объявленные пути недоступны и есть дескрипторы, выполняется
виртуальный импорт. У Shell-объектов с CF_HDROP тестируется прежний путь,
а у объектов без CF_HDROP — прямое потоковое чтение.
