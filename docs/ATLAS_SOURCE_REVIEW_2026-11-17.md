# Papka и открытые исходники Atlas — 17.11.2026

Источник: github.com/neondeex/atlas-filemanager (один коммит от 12.11.2026,
версия 0.1.5). Раньше Atlas сверялся только по скриншотам и видео.

**Лицензия Atlas — AGPL-3.0-or-later.** Копировать или пересказывать близко к
тексту его код в Papka нельзя (иначе Papka тоже обязана стать AGPL). Можно
смотреть идеи и устройство и писать своё.

## Масштаб

| | Papka | Atlas |
|---|---|---|
| Строк Rust (без vendor) | ~29 тыс. | ~175 тыс. (UI 115 тыс.) |
| Тестов `#[test]` | ~325 | ~720 |
| GPUI | gpui-ce 0.2.2 с crates.io + патч Windows drop | свой форк gpui-ce + форк gpui-component (анимации, плавная прокрутка, кэш сцены) |
| Языки | русский | 10+ (rust-i18n) |
| Платформы | Windows | Windows, Linux-пакеты в разработке |
| Распространение | портативный ZIP + своё автообновление | Microsoft Store, Free/Premium |

## Что есть у Atlas и нет у Papka

- Виды: сетка, подробный, дерево; Papka — список, Миллер, плитки.
- Число панелей не ограничено (у Papka — до четырёх, тоже деревом).
- Поиск по всему тому через MFT/USN (`atlas-search-service`, `volume_index.rs`),
  нечёткий поиск nucleo, поиск по содержимому. У Papka — индекс SQLite папки
  и `notify`.
- Архивы как папки: ZIP, RAR, 7z, TAR (у Papka — zip).
- Конвертация файлов (ffmpeg, Pandoc, Opus) с радиальным меню.
- Облака через rclone, SMB/FTP/WebDAV в боковой панели.
- Приватные папки с паролем (vault), очистка диска и «Space Lens» по MFT.
- Расширения (манифест + sidecar-процессы), темы и пакеты значков VS Code,
  редактор тем, переназначение клавиш.
- Анимации на пружинах, стеклянные поверхности, отчёты о сбоях с символами.

## Что есть у Papka и нет у Atlas

- История файлов (только метаданные): кто, когда, комментарий, учёт версий
  `_v_1_6` и блок «Версии».
- Миниатюры и предпросмотр DWG без AutoCAD.
- Сравнение папок, проверка копий, журнал операций с восстановлением,
  поэтапное копирование без перезаписи.
- Проекты внутри панели с карточкой объекта и «Входящими», лента, метки, правила для сетевых путей (DFS/UNC).
- Повторный запрос списка при drop (работа с 7-Zip) — патч `gpui_ce_windows`.

## Что стоит взять как идеи (своей реализацией)

1. Единый конвейер переноса `validate → detect_conflicts → диалог → execute`
   с отчётом по каждому элементу — сверить с нашей очередью и диалогом замены.
2. Исключения для фоновых обходов (`scan_policy.rs`: Windows, ProgramData,
   приватные пути) — для индекса и наблюдателей.
3. Поиск по тому через USN Journal — давно в планах README; у Atlas видно, что
   это отдельный процесс-служба с правами.
4. Плавная прокрутка колёсиком и анимации панели сведений — у них сделаны
   патчами GPUI; для нас дорого (свой форк), брать только если очень нужно.
5. Нечёткий переход к папке (Ctrl+K) с ранжированием nucleo.
6. Восстановление после паники рабочих потоков и «отравленных» блокировок
   вместо закрытия приложения.

## Анимации Atlas по коду

Общие длительности в `ui/motion.rs` (80–240 мс, профиль «demo snappy»):
появление строк при открытии папки (90 мс, сдвиг по 4 мс на строку),
сдвиг содержимого при переходе по папкам (`views/transition.rs`), раскрытие
и закрытие разделения (240/140 мс), пружинное появление боковой панели и
панели сведений, вкладки раздвигаются при перетаскивании и закрытии (150 мс),
плавный ход колёсика (патч GPUI), пульсация цели при перетаскивании,
пружинные флажки выделения, плавная подсветка при наведении, размытие
«стекла» 12 px под всплывающими окнами, автопрокрутка у края при
перетаскивании. Есть настройка «меньше движения».

В Papka уже есть: проявление палитры и меню (120–130 мс), открытие папки при
удержании перетаскиваемого файла (`spring.rs`, 700 мс), мгновенная навигация.
Вывод: заметную разницу дают только плавное колёсико и автопрокрутка у края;
остальное — оформление, которое в работе с файлами почти не помогает.

## Разбор пунктов 1–5 (сделано 17.11.2026)

1. **Конвейер переноса.** У нас уже были проверки «внутрь самой себя»,
   «всё уже в этой папке», диалог конфликта и отчёт по каждому элементу.
   Добавлено: `DropZone::prune_for` убирает объекты внутри другой выбранной
   папки и (при перемещении) уже лежащие в целевой папке — раньше они
   давали ошибку «уже существует». Диалог конфликта показывает, какой файл
   новее, и размеры обоих (`operations::Conflict`).
2. **Исключения фоновых обходов.** `core/scan_policy.rs`: поиск, индекс и
   его обновления не заходят в %WINDIR%, %ProgramData%, %TEMP%,
   %LOCALAPPDATA%\Temp, профиль Papka, а также в `$Recycle.Bin`,
   `System Volume Information`, `$WINDOWS.~BT`, `Config.Msi`, `.git`.
   Если обход начат внутри такой папки — она просматривается. Подсчёт размера
   папки по-прежнему считает всё.
3. **USN Journal — решено не делать сейчас.** Чтение журнала и MFT требует
   открыть том `\\.\C:` с правами администратора: Atlas делает это отдельной
   службой (`atlas-search-service`) или помощником с запросом UAC
   (`mft_space/helper.rs`). Для портативной Papka без установки это значит
   UAC при каждом запуске или установку службы. Главное — журнал есть только
   у локальных NTFS-дисков; на сетевых DFS/SMB-папках, где работает
   пользователь, его нет вообще. Текущая схема (индекс SQLite по папке +
   уведомления + опрос сети) покрывает эти папки. Вернуться, если понадобится
   мгновенный поиск по всему локальному диску: отдельный необязательный
   помощник с одним запросом UAC, только чтение, результат по каналу.
4. **Нечёткий переход.** `jump::letters_score` — оценка «буквы по порядку»
   по образцу nucleo: начала слов +16, подряд идущие +8, разрыв −3. Слово
   целиком в имени по-прежнему выше.
5. **Сбои.** В Windows-версии GPUI фоновые задачи идут в системном пуле
   потоков через `extern "system"`: паника там закрывает процесс без
   сообщения. Добавлено `core/guard.rs`: журнал `crash.log` в профиле
   (сообщение, место в коде, поток — без содержимого файлов), сообщение о
   прошлом сбое при запуске, `guard::catch` вокруг разбора чужих файлов (DWG,
   миниатюры, таблицы, архивы), `guard::lock` — блокировки, не «отравляемые»
   паникой другого потока (наблюдение за папками, Корзина, буфер обмена).

Анимации: автопрокрутка у края при перетаскивании (`edge_scroll.rs`),
мягкое появление содержимого папки (110 мс, только прозрачность, ввод не
блокируется), выезд панели переноса. Плавное колёсико — без правки GPUI
(`smooth_scroll.rs`): невидимый слой поверх списка ловит колесо в фазе
перехвата (Capture), останавливает событие и сам ведёт тот же ScrollHandle
к цели с замедлением (τ = 50 мс), по шагу на кадр в prepaint слоя (слой стоит перед списком, без таймеров: таймер 8 мс давал рывки на Windows). Только колесо мыши (ScrollDelta::Lines);
тачпад (Pixels), Shift и Ctrl остаются GPUI.
