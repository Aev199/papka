# Быстрая загрузка снимков во входящих — 20.11.2026

Причины задержки по коду: открытие карточки не запускало чтение входящих немедленно (оно могло ждать первого четырёхсекундного опроса); для изображений 140×84 GPUI получал исходные PNG/JPEG целиком, до 40 файлов одновременно.

Исправлено:

- Чтение входящих начинается при открытии карточки. Уже выполняющийся запрос той же папки не дублируется; устаревший результат не подменяет список после смены проекта/папки.
- Подготовка превью отделена от отрисовки. Две фоновые задачи делают маленькие PNG до 280×280 (с запасом для DPI), результаты показываются по одному, без ожидания всего пакета. Новые снимки идут первыми. Исходник по щелчку открывается как раньше.
- Кэш находится в `%LOCALAPPDATA%/Papka/thumbnails/inbox`, ключ включает путь, размер и дату изменения исходника. При повторном открытии проверяется локальный PNG, повторного чтения/декодирования исходного снимка для готового кэша нет. Текущее состояние берётся из метаданных списка входящих.
- Очередь содержит только показываемые записи, удаляет повторы и незапущенные задания закрытого проекта. Повреждённые картинки получают заглушку с открытием оригинала; временные ошибки можно повторить очередным опросом. Чтение/декодирование ограничено по размеру и памяти.
- Список JSON сначала сортируется по свежести, после 300 корректных записей чтение старых прекращается. Метаданные снимка читаются один раз вместе со списком.

Проверка:

- 345 тестов workspace прошли. Новые проверки покрывают 4K PNG, JPEG, повторное использование и восстановление повреждённого кэша, ограничения размера, изменение исходника, два одновременных задания, приоритет, устранение дублей и игнорирование устаревшего результата.
- Проверка всех целей для Windows GNU прошла; отдельные layout/palette, привязки клавиш и отмена перетаскивания также проверены.
- В Linux GUI открыт проект с шестью PNG 3840×2160. Все миниатюры показаны; шесть файлов кэша занимали 25 897 байт. Повторное открытие не изменило ни имён, ни времени записи кэша. Замена последнего исходного PNG под тем же именем отразилась новой миниатюрой при очередном опросе.
- В отдельном локальном debug-тесте на синтетическом 4K PNG подготовка первого превью заняла около 899 мс, чтение готового кэша — около 2 мс. Это измерение функции обработки на данной машине, а не обещание времени открытия карточки на Windows/сетевом диске.

Формат обмена с Notch не изменён. Четырёхсекундный интервал последующих проверок новых записей сохранён; ожидание убрано именно при открытии карточки. Windows Shell для подготовки этих превью не используется.
