# «Входящие» проекта: формат обмена Papka ↔ Notch

Notch (и любая другая программа) отправляет в проект Papka снимок, текст
или ссылку на файл: «В проект…» → выбрать проект → подпись → «Отправить».
Papka показывает поступления в карточке проекта, в разделе «Входящие».
Программы не связаны ничем, кроме двух файлов, описанных здесь; Papka может
быть закрыта, когда Notch пишет.

## 1. Список проектов: `%LOCALAPPDATA%\Papka\projects.json`

Пишет Papka — при запуске и после создания, удаления, открытия или
закрытия проекта и смены папки объекта. Запись атомарная (временный файл и
переименование). Читатель файл не меняет.

```json
{
  "format": 1,
  "program": "Papka",
  "projects": [
    {
      "id": "p-6d3587282525dcab",
      "name": "Корпус 2",
      "root": "Z:\\Объекты\\044 Сити-2\\Корпус 2",
      "inbox": "Z:\\Объекты\\044 Сити-2\\Корпус 2\\_Входящие"
    }
  ]
}
```

- `id` — постоянный номер проекта. Не меняется, пока проект не удалён;
  у нового проекта с тем же именем номер другой. Ссылаться на проект
  нужно по нему, а не по имени.
- `root` — папка объекта; может отсутствовать.
- `inbox` — куда писать записи. Это `<root>\_Входящие`, а без папки
  объекта — `%LOCALAPPDATA%\Papka\inbox\<id>`. Папки может ещё не быть:
  её создаёт отправитель.

### Как Papka определяет папку объекта

1. Задана вручную в карточке («Сделать папкой объекта» у папки проекта).
2. Иначе — папка, где лежит паспорт объекта `object.json` (в папках
   проекта или до пяти уровней выше).
3. Иначе — общая папка всех вкладок проекта, но не корень диска или
   сетевого ресурса (`Z:\`, `\\сервер\ресурс`).
4. Иначе папки объекта нет, и входящие хранятся в профиле Papka.

## 2. Запись во «Входящих»

Одна запись — это `<имя>.json` и, для снимка, `<имя>.png` рядом.
Имя: `ГГГГММДД-ЧЧММСС <подпись>`, подпись без `\ / : * ? " < > |`, до 60
знаков; при совпадении — ` (2)`, ` (3)`… Например
`20261117-143205 Сверить привязку С-18.png` и `.json`.

Порядок записи обязателен: сначала картинка, потом `.json`, каждый —
через временный файл (`….tmp`) и переименование. Papka читает только
`.json`, поэтому никогда не видит половину записи.

```json
{
  "format": 1,
  "kind": "image",
  "created": "2026-11-17T14:32:05+03:00",
  "caption": "Сверить привязку С-18 с разбивочным планом",
  "image": "20261117-143205 Сверить привязку С-18.png",
  "source": { "app": "acad.exe", "window": "Корпус 2 — Свайное поле.dwg" },
  "project": "p-6d3587282525dcab"
}
```

| Поле | Значение |
|---|---|
| `kind` | `image` — снимок, `text` — текст, `file` — ссылка на файл или папку |
| `created` | местное время с часовым поясом (RFC 3339) |
| `caption` | подпись пользователя, может быть пустой |
| `image` | имя PNG рядом (только имя, без пути) — для `image` |
| `text` | сам текст — для `text` |
| `file` | путь к файлу или папке — для `file`; у снимка — документ, с которого он снят, если известен |
| `source` | программа и заголовок окна, откуда материал |
| `project` | номер проекта из `projects.json` |

Ссылка на файл (`file`) не копирует файл: в записи только путь.

## 3. Что делает Papka с записями

Показывает их в карточке проекта, раздел «Входящие»: миниатюра,
подпись, время, источник, текст или ссылка. Единственное, что Papka
меняет в чужой записи, — поле `caption`: щелчок по подписи позволяет её
написать или исправить; остальные поля файла остаются как есть, файл
переписывается целиком через временный. Действия:

- **В заметки** — подпись, текст и путь к снимку дописываются в первый
  раздел карточки (путь становится ссылкой);
- **Показать в папке** — папка входящих в новой вкладке, запись выделена;
- **Удалить** — снимок и `.json` в Корзину через журнал (`Ctrl+Z`).
  Перенести, переименовать или удалить запись можно там обычными
  командами Papka (через журнал и `Ctrl+Z`).

Пока карточка открыта, Papka заглядывает во «Входящие» раз в несколько
секунд: отправленное из Notch появляется само.
