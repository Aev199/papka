# Обновления Papka

## Выпуск новой версии

1. GitHub → Actions → «Windows portable EXE (manual)» → Run workflow,
   ветка `feat/native-gpui-foundation`.
2. Поля запуска:
   - **channel**: `beta` — тестовая сборка (её получают только те, у кого
     в настройках выбран канал «Все сборки»); `stable` — для всех.
   - **publish**: снять флажок, если нужна только сборка без выпуска.
   - **notes**: что нового, пункты через `;`. Пусто — берутся заголовки
     коммитов с прошлого выпуска.
3. Сборка получает версию `0.1.<номер запуска>` и публикует выпуск
   `v0.1.N` с файлами `Papka.exe`, `latest.json`, `Papka-win64.zip`.

Канал по умолчанию в программе — «Стабильные», поэтому стабильный выпуск
стоит делать после каждой проверенной беты: иначе пользователи с
настройками по умолчанию остаются на старой версии.

Бета-выпуск можно сделать стабильным позже: на странице выпуска снять
отметку «Set as a pre-release».

## Как обновляется программа

- Раз в сутки (и по кнопке в «О программе») Papka запрашивает список
  выпусков GitHub через системный WinHTTP — с прокси, как в браузере.
  Нет сети — проверка молча пропускается.
- Загруженный `Papka.exe` сверяется с SHA-256 из `latest.json`.
- Работающий EXE переименовывается в `Papka.old.exe`, новый ставится на
  его место; при ошибке на любом шаге всё возвращается как было.
- Перезапуск сохраняет вкладки и панели и не выполняется во время
  копирования/переноса.
- «Вернуть предыдущую версию» меняет `Papka.exe` и `Papka.old.exe` местами.
- Локальные сборки (`-dev`) сами не проверяют обновления.
- Загрузка больше 512 МБ отклоняется: это не Papka.
- EXE не подписан сертификатом. SHA-256 защищает от повреждения при
  загрузке и от подмены файла в «Загрузках», но не от подмены самого
  выпуска на GitHub.

## Если программе закрыт интернет (брандмауэр пускает только браузер)

- Проверка показывает «Нет доступа к GitHub» и кнопку «Скачать в
  браузере»: браузер сразу скачивает `Papka.exe` в «Загрузки» — на
  стабильном канале последнего стабильного выпуска, на бета-канале самой
  свежей сборки. Папка 20 минут следит за «Загрузками» (и проверяет их
  каждый час) и предлагает установить найденный файл — версия читается из
  свойств EXE, «Papka (1).exe» тоже подходит.
- Файл из «Загрузок» сверяется с выпуском его версии: SHA-256 должен
  совпасть с `latest.json`. Совпал — в окне «Файл сверен с выпуском» и
  список изменений. Не совпал или такой версии среди выпусков нет — файл
  не предлагается. Если GitHub недоступен и сверить нельзя, файл
  предлагается с красным предупреждением: ставить его стоит, только если
  вы сами скачали его со страницы Papka.
- У GitHub постоянная ссылка `releases/latest` ведёт только на стабильный
  выпуск, поэтому каждая публикация ещё кладёт `Papka.exe` в отдельный
  выпуск с тегом `beta` («Papka: последняя сборка»): ссылка бета-канала —
  `releases/download/beta/Papka.exe`. В этом выпуске нет `latest.json`, и
  Папка не предлагает его как обновление.
- В сообщении об ошибке — одна строка о причине (код WinHTTP и текст
  ошибки запасного способа через PowerShell, без служебного вывода).
